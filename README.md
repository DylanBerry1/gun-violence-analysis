# gun-violence-analysis

Chicago crime-analysis pipeline for studying homicide patterns with hex-based spatial aggregation, correlation analysis, and XGBoost prediction.

The repository is organized so a reviewer can inspect the current results directly in GitHub and a contributor can rerun the pipeline from `src/` without relying on stale notebook logic.

## Project Scope

The current codebase focuses on Chicago homicide patterns and nearby spatial context:

- homicide incidents from the City of Chicago crime data
- drug-crime incidents used as a related risk signal
- the full Chicago Crimes dataset for all-crime correlation analysis
- OpenStreetMap infrastructure locations
- Chicago socioeconomic indicators by community area

The common unit of analysis is a 500 meter axial hexagon. The same grid supports mapping, correlation analysis, feature engineering, and predictive modeling.

## Repository Layout

- `src/`: operational source of truth for the pipeline
- `data/raw/`: required source CSV inputs
- `data/processed/hex/`: generated hex-level outputs for mapping and downstream analysis
- `data/processed/modeling/`: generated modeling table
- `data/processed/crime_infrastructure_hex_merged.csv`: merged table from the all-crimes correlation stage
- `reports/maps/`: committed Folium map outputs
- `reports/figures/`: committed static figures, correlation outputs, and interactive rank-order HTML
- `reports/modeling/`: committed metrics, holdout predictions, and feature-importance outputs
- `report/`: written project report and background narrative
- `notebooks/`: exploratory work with some stale assumptions and brittle paths
- `.agents/skills/gun-violence-analysis-pipeline/`: repo-local Codex workflow guide for the pipeline

When documentation, notebooks, and generated outputs disagree, prefer the scripts in `src/`.

## Canonical Workflow

Run commands from the repository root.

### 1. Refresh infrastructure locations

```bash
python3 src/build_infrastructure_data.py
```

Use this only when `data/raw/infrastructure_locations.csv` needs to be regenerated from OpenStreetMap. The script requires live network access and overwrites that CSV.

### 2. Build hex maps and processed hex tables

```bash
python3 src/build_hex_maps.py
```

Main outputs:

- `reports/maps/crime_hex_maps/chicago_hex_map.html`
- `data/processed/hex/chicago_homicides_hex_counts.csv`
- `data/processed/hex/chicago_drug_hex_counts.csv`
- additional per-crime `*_with_hex.csv` and `*_hex_time_season_counts.csv` files under `data/processed/hex/`

The interactive map supports multiple hex sizes, but the persisted CSV outputs are only written for the default `500m` size.

### 3. Recompute all-crime and infrastructure correlation outputs

```bash
python3 src/build_correlation_analysis.py
```

Main outputs:

- `data/processed/crime_infrastructure_hex_merged.csv`
- `reports/figures/correlation_crime_vs_homicide.png`
- `reports/figures/correlation_matrix_all_crimes.png`
- `reports/figures/correlation_matrix_crime_infrastructure.png`
- `reports/figures/top_infrastructure_correlations.png`
- `reports/figures/correlation_summary.txt`
- scatter plots for the strongest crime-type and infrastructure relationships under `reports/figures/`

This stage requires the large full-crimes CSV named `data/raw/Crimes_-_2001_to_Present_20260408.csv` unless the script is updated.

### 4. Train the hotspot and count models

```bash
python3 src/train_xgboost_hex_model.py
```

Main outputs:

- `data/processed/modeling/chicago_hex_modeling_table.csv`
- `reports/modeling/hotspot/xgboost_metrics.json`
- `reports/modeling/hotspot/xgboost_holdout_predictions.csv`
- `reports/modeling/hotspot/xgboost_feature_importance.csv`
- `reports/modeling/count/xgboost_metrics.json`
- `reports/modeling/count/xgboost_holdout_predictions.csv`
- `reports/modeling/count/xgboost_feature_importance.csv`

The script defaults to `--task all` and `--hex-size-m 500`.

### 5. Rebuild the rank-order plots

```bash
python3 src/build_rank_order_plot.py
```

Main outputs:

- `reports/figures/homicide_rank_order_plot.png`
- `reports/figures/interactive_rank_order.html`

This stage depends on `data/processed/hex/chicago_homicides_hex_counts.csv` from the hex-map stage.

## Notes For Contributors

- Prefer the scripts in `src/` over notebooks when verifying current behavior.
- Keep the default `500m` hex size unless you intentionally want to regenerate downstream artifacts at a different scale.
- Do not hand-edit generated CSV, HTML, JSON, PNG, or model artifacts.
- If you change runtime dependencies, update `requirements.txt` in the same change.
